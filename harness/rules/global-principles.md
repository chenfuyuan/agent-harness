# 跨项目全局工程与安全底线（Global Principles）

> 本文件定义所有接入 `agent-harness` 的下游仓库（应用开发、数据分析、部署运维等）默认继承的通用工程红线。

## 1. 环境与职责物理隔离
- **内部工具/实验工程 vs 对外商业产品隔离**：内部自用工具、探索实验与对外生产服务分仓、分环境、分凭证部署，不混用数据库、计费与权限底座。
- **方法论引擎 vs 运行实例隔离**：母仓只沉淀可复用的 AI 技能（Skills）、门禁（Guards）与脚手架；具体业务代码、真实服务器编排配置与业务数据集一律归属独立下游仓库。

## 2. 确定性计算与 AI 资产化铁律
- **能算不用 AI**：数值计算、统计指标、规则阈值与账目核对必须由确定性程序完成；AI 引用的任何统计或金额数字必须来自确定性程序且可溯源。
- **高成本推理留资产**：昂贵的 AI 深度调研、架构推演或结构化分析结果应落盘为可增量复用的结构化文件，避免无状态重复全量重跑。
- **交互态与无人值守分流（信任阶梯）**：人在场的探索/草稿生成坚持“AI 交草稿、人拍板”；无人值守定时批处理或自动化 Bot 必须明文声明 **Anti-Job（严禁越界动作 + 无事静默禁刷屏）**、最小工具权限与硬预算熔断护栏，按“草稿人审 → 沙箱自验 → 限额自动”信任阶梯放权。
- **非授信边界隔离与确定性止损（Checks over Notes）**：外部/AI 输出入库实行“原值严校 + 不限长审计区保真留证（定长列仅在落盘边界截断）+ 单件死信隔离防连坐”，严禁拿改提示词或裸类型/Lint 消音（`@ts-ignore` / `# type: ignore` / `# noqa`）代替确定性代码校验护栏；瞬时抖动走有界退避重试，同输入必复现的确定性错误按状态水位锁死零重复重试。

## 3. 密钥、资金与生产变更绝对红线
- **零密钥入库**：严禁任何 API Key、私钥、助记词、Cookie、生产连接串进入仓库文件、提交说明或静态原型页面；统一经本机环境变量或 `.gitignore` 保护的本地配置注入。
- **高危动作显式授权**：AI 在未获当次明确授权前，严禁发起任何真实资金划转/下单、生产环境破坏性变更或付费云资源创建。

## 4. 上下文卫生与两级代码导览（Context Hygiene）
- **两级人工导览 + 单一规则真源 + 按需 AST 骨架**：长文档顶部保留 ≤35 行 `TL;DR` 速查；模块公开入口、分层依赖与高危 API 封禁统一收口在项目根 `.harness-rules.json`（由 `ws check` 自动执行）；仅复杂核心模块按需维护 ≤20 行（硬上限 25 非空行）`src/<mod>/AGENTS.md`（只写机器检不出的纯业务不变量与单测命令，简单模块不建）；**源码文件顶部只写 1–2 行职责与隐性契约，严禁手写函数清单或行号目录**（类名、函数签名与行号一律由 `ws map <dir|file>` 与 `read_guard.py` 实时 AST 提取，杜绝注释腐烂）。
- **漏斗式探索与按段精读**：摸底陌生代码先读模块 `AGENTS.md` 或跑 `ws map <dir>` 获取 `[Lstart-Lend]` 骨架，再用 `rg -n` 定位并按行段（单次 ≤360 行）精读；禁止对 >400 行文件无行号整本吞读（双端 `PreToolUse` `read_guard.py` 会自动拦截并当场返回结构骨架）。
- **热缓存精读与广度探索隔离**：小范围定位与修改（≤8 个文件）留在主会话并行按行段精读以复用前缀缓存；跨目录盲找 >8 个未知文件时派只读子代理隔离检索噪音（单子代理 ≤15 个文件，防自身触发压缩），仅回传结构化结论与精确 `文件路径:行号`，即将修改的文件与核心算式须由主会话亲读原文。
- **压缩后重验锚点**：若长会话经历过上下文自动压缩，修改任何文件前必须先按行号重读目标位置上下 30 行核对最新文本，严禁凭压缩摘要记忆盲改。

## 5. 本地全量硬凭证、开发态复用与云端零容器节流（CI Quota & Gate Hygiene）
- **重测留本机、凭证跨线复用锁发布**：重型全量检查（多容器编排、数据库迁移、浏览器端到端）一律在本机运行，通过后将非文档代码树指纹签发至 Git 公共目录共享凭证（`ws check --record-full`）；开发线送审、复核与合线反复执行全量检查时先用 `ws check --full-covered` 核验当前工作区代码树是否已在本机任一工作树跑通（命中即免重跑，显式 `--force` 强制重跑），打版本标签与上线推送前强制核验提交凭证（`ws check --verify-full HEAD`），纯文档与设计改动不使已验代码凭证失效。
- **快停剖析 + 分级内循环**：开发过程按金字塔分流（零数据库 `--unit` 纯内存单测 → 复用测试库指定文件 `--quick` → 按改动增量 `check` → 全量 `--full`）；全量门禁接入失败快停（如 `--ff --maxfail=10`）、逐阶段计时、耗时剖析开关与按文件大小倒序投递的动态并发线程池，优化一律基于实测 profiling 驱动。
- **禁分支双烧、云端守底线**：个人与小团队私有仓严禁同时对 `push main` 与 `push v*` 跑重型容器流（防同一提交双倍烧穿月度免费 CI 分钟配额）；云端 CI 仅在 `push tags: ["v*"]`、`pull_request` 与 `workflow_dispatch` 触发，开启 `concurrency.cancel-in-progress: true` 与短超时（`≤10 min`），只跑 <1 分钟零容器硬底线（全仓密钥扫描、架构与模块公开入口边界、只加不删迁移守卫及纯标准库关卡自测）。
