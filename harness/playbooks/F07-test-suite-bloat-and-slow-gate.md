# F07：测试套件膨胀、重复建库与慢门禁治理（零覆盖损失提速）

- **触发场景**：编写或重构含数据库、数据湖、异步并发、长窗口历史回补的自动化测试，或设计项目级 `scripts/check` 分层与全量门禁时。
- **典型错的样子（测试越积越慢、改一行等 10 分钟）**：
  1. **只读测试每条重建世界**：多条只读查询、空态、越权或参数校验用例各自在函数级夹具里跑全套流水线同步建库，导致 `setup` 占比超过一半；
  2. **独立空库测试每条重跑全量迁移**：备份/恢复/升级隔离类测试每条建空库顺序执行 50+ 表迁移，而非从已迁移模板库克隆；
  3. **纯内存与连库道串台**：简单输入校验或纯函数规则写进连库测试白跑建库；反过来纯内存 `_rules` 测试偷偷加载嵌入式数据湖/磁盘库扩展或网络套接字，悄悄把秒级单元道拖成十几秒 I/O 测试；
  4. **照搬生产大样本、长等待与旁路泄漏**：测试里塞多年历史、上百实体或真实 `sleep(1–3s)` / 50 次上限，或未关闭无关旁路步骤（如外部抽查、未用到的大批参照表），白烧 I/O 与超时等待；
  5. **惰性建表拆散强耦合主表组**：优化造数辅助时只建半套强关联核心表（如只建主事实表漏建伴生因子/状态表），导致同 worker 后续共享库测试撞缺失表雪崩。
- **治本做法**：
  1. **先剖析再动刀，按金字塔分流**：全量门禁内置耗时剖析开关（如 `durations=0`）与失败快停（`--ff --maxfail=N`），先找占 70%+ 耗时的头部文件再治理；纯逻辑一律入零 I/O 单元道，并在架构守卫里同步封禁纯内存测试引用 DB、数据库夹具与加载嵌入式数据湖/磁盘库扩展；
  2. **共享不可变基座 + 模板库克隆**：只读用例组升至模块/类级共用一份不可变基座（只清本用例写到的少量业务表，注意类级夹具放模块顶层避 pytest 警告）；需要独立整库的测试从已迁移模板库克隆（`CREATE DATABASE ... TEMPLATE <tpl>`，持跨进程锁防并发模板冲突）；
  3. **强关联表组整建、松耦合附属表惰性建**：核心强耦合主表组作为整体一次建齐，仅对松耦合附属/参照表按需惰性建表；非集成主路径测试直调目标子步骤，显式关闭无关旁路；
  4. **先断言生产默认常量，再打桩缩小规模**：缩小批上限、等待轮次或超时前先 `assert DEFAULT == 生产值` 守住配置防误改，再用最小边界样本（如 `n=1~3`、跨月 2–4 天、极短超时）测透全部逻辑分支；
  5. **防假优化三铁律**：严禁删除历史跨版迁移防线或抽样跳过逐处打断（`each_commit`）提交点；提速后必跑 AST 级断言变更审计（核对 0 断言弱化，每处合并/删重可逐一溯源）。
- **必配测试**：① 架构守卫回归测试验证纯内存测试加载真实 DB/数据湖扩展会被硬拦截；② 全量提速前后保留基线与优化后完整耗时日志对照，并全绿跑通所有保留的历史迁移与逐处打断测试。
