# F01：非授信输入边界、保真留审与单件死信隔离

- **触发场景**：处理外部数据源、第三方回调、用户自由输入或大模型结构化输出，经业务规则核实后写入权威正本与审计/错题表。
- **典型错的样子（浅补丁反模式）**：
  1. **扩正本洗白脏数据**：上游或 AI 吐出超长草稿/越界枚举导致入库崩溃时，顺手放宽正本列宽或校验白名单让脏数据混入正本；
  2. **提前截断毁灭审计现场**：在送进校验器之前就粗暴截断输入字符串，导致不限长的拒绝原因或原始日志也丢失了后半截异常证据；
  3. **单粒坏件炸毁整批**：批处理循环中某一条或某一篇文档结构损坏抛错，未做单件隔离，导致整批合法数据回滚且坏件永远停在“待处理”死循环；
  4. **历史死信污染现态看板**：死信/错题表采用 append-only 保留历史证据，但状态看板或告警统计按日期/全局聚合全部行而未绑定最新有效批次 `run_id`，导致修好重跑成功后旧历史死信永远挂红假报警。
- **治本做法**：
  1. **原值严校**：完整未裁剪的原始值直接送入纯函数校验器，严格守住枚举、范围与业务不变量，不合规一律标为 `rejected / failed`；
  2. **双区留痕、后置截断**：在 `JSONB / Text / 原始报文层` 100% 原样保留完整原始输入与完整拒绝理由；仅在写入定长摘要索引列（如 `VARCHAR(N)`）的最终持久化边界做长度截断；
  3. **单件舱壁隔离（Bulkhead）**：逐条/逐文档建立异常隔离边界，坏件落入死信或失败状态并记录脱敏错误摘要，同批其余合法记录与下游步骤照常推进；
  4. **留底与现态作用域分离**：死信与审计日志只追加不删，但健康计数、阻断判定与前端展示一律按各数据集最新有效运行批次 `run_id` 作用域聚合（兼顾尚无成功批次时的回退展示），修通重跑后现态自动归零。
- **必配测试**：构造超长越界值 + 结构损坏样本与正常样本混装同一批，断言：① 正本零脏数据；② 审计区完整包含未截断异常原文；③ 同批正常样本成功生效且坏件不再被重复捞起；④ 修通样本重跑新批次成功后，历史死信仍可溯源但最新现态视图死信计数归零。
