# F09：解析器差异、默认放行与运维自锁陷阱

- **触发场景**：编写生产部署/发版脚本、容器编排（Docker Compose）、环境变量/数据库连接串/路径边界校验，或运维控制 CLI 时。
- **典型错的样子（边界失效与故障自锁）**：
  1. **校验器与执行器解析差异（Parser Differential）**：守卫脚本用 `grep "^KEY="` 读配置，但下游运行器（如 Compose `--env-file`）支持 `export KEY=VAL`、`KEY = VAL`、行尾 `#` 注释或变量插值；或校验完未钉死环境变量，导致执行器另读到未审值绕过库隔离/路径护栏；
  2. **按 HTTP URL 思路粗校连接串与裸拼密码**：数据库客户端（如 `libpq`）不将 `#` 视为 fragment 且会对 query 参数键做 `%xx` 百分号解码（如 `?x#&dbname=other`、`?%64bname=other`），且未校验的密码裸插 DSN 若含 `@ : / ? # %` 会改写目标库或主机；
  3. **漏默认拒绝与控制字符绕过**：路径/白名单 `case` 分支缺少 `*)` 默认拒绝导致拼写错误静默放行；`grep -F "$var"` 未拒换行符 `\n` 被拆成多行模式匹配任意输出；
  4. **容器资源双限错配与假赋权**：应用内内存上限（如嵌入式分析引擎）× 并发槽大于容器 `mem_limit`，或轻量 API 容器继承重型任务默认限额致 cgroup OOM；盲信 `chown` 成功（无视 GID 错配、外置卷 `noowners` 静默忽略或对海量文件慢速递归 `chown -R`）；
  5. **只读排障通道自锁**：`status` / `logs` 等只读诊断命令耦合了写入类前置检查（如外置卷挂载硬拦、`mkdir -p` 或依赖首次安装成功后才写入的版本文件），导致首次安装失败或掉盘时连日志都看不了。
- **治本做法**：
  1. **校验即传参、强制默认拒绝**：所有受控参数（DB 库名/连接串/宿主机目录/端口/版本）在校验后经进程环境变量显式钉死传给执行器；连接串护栏拒绝 `#`、空白、控制字符与 query 键 `%` 编码，裸密码插 DSN 必校 URI 保留字符；路径与枚举校验必须带 `*)` 默认拒绝并先拒控制字符；
  2. **资源双限对齐与非特权实检**：按轻/重容器分别设定应用内存上限，保证 `应用上限 × 并发度 + 运行时开销 < 容器 mem_limit`；数据目录只做 O(1) 顶层及固定工作目录 `chown user:group`，并紧跟以真实非特权运行用户执行 `test -w` 预检失败快停；
  3. **只读诊断与运行预检解耦**：`status` / `logs` 走独立只读加载路径（不跑挂载硬拦与 `mkdir`、允许无版本标记时回退默认），确保系统出故障时排障入口永远畅通。
- **必配验证**：对边界校验函数做红灯用例自测（`#`/百分号参数键/含 `@` 密码/换行路径/拼错前缀路径/前导零端口均应失败）；用 `docker compose config` 核对轻/重容器最终渲染限额；验证首次安装失败或断卷场景下 `logs` / `status` 仍可执行。
