# F05：防规模增长后的小文件爆炸、扩展目录无索引全扫与读路径放大

- **触发场景**：引入数据湖/第三方存储扩展（如 DuckLake/Iceberg 目录库）、按分区分批回补多年历史数据、为高频读页面组装多表/长文本上下文，或跨隧道/公网交付单页前端（SPA）。
- **典型错的样子（小样本正常、上量后雪崩）**：
  1. **盲信扩展自建目录表已有索引**：ORM 外键或第三方数据湖扩展自动建出的元数据/关联表默认零二级索引；测试库百行毫秒级返回，生产库涨到百万行后，哪怕查单行小表也会触发数百 MB 元数据顺序全表硬扫；
  2. **分区分批写入延迟到收尾才合并**：$M$ 个历史批次跨 $P$ 个时间分区切块写入，却只在 `remaining == 0` 全部跑完时调一次无界文件合并，中途制造 $M \times P$ 十万级碎文件拖垮全站，且收尾无界合并极易撑爆 worker 内存（OOM）；
  3. **读路径无界全表预取、同页隐式双算与隐藏面板偷跑**：为拼几条证据把数万行长文本整表 `SELECT *` 拉入内存；对不可变快照反复实时跑十亿行 `COUNT/MIN/MAX`；前端首屏同步 import 全站路由页面与重型编辑器/图表库，挂载未激活 Tab 偷跑慢查询，或 `staleTime` 仅设数秒切窗口即全站重刷。
- **治本做法**：
  1. **底座幂等锁死目录二级索引**：平台存储层首次可写连接与 `migrate` 时先查系统目录（如 `pg_indexes`），缺索引才幂等补齐 `(table_id, data_file_id)` 等热点组合索引（免日常读连接争抢 DDL 锁），并用连库单测硬断言索引存在；
  2. **写入中按水位有界增量合并**：分批回补任务在 `publish()` 前检测待合并碎文件数达阈值即执行带 `max_files` 上限的有界合并，并提供持锁校验“纯物理合并零行变更”后原地推进快照指针的收口命令；
  3. **按需主键点查 + 不可变快照/水位单航道缓存**：长文本底表强制先缩窄候选 ID 再按列投影读取；不可变数据版本（`snapshot_id`）与多表聚合按真实状态指纹/水位元组做有界单航道缓存（严禁用字符长度和充当状态水位防等长碰撞，返回深拷贝防原地污染）；
  4. **路由全量懒加载、发版分包自愈与传输缓存分层**：所有路由页强制 `lazy()` 拆包（配单测守卫防同步回退），并在壳内挂载子路由错误边界与 `vite:preloadError` 单次自动刷新守卫（防发版后常驻旧标签页点新菜单 `404` 击穿顶栏白屏）；未激活 Tab 设 `enabled: false` 且禁在空筛选条件挂载时自动扫全表；服务端开启 `GZip` 压缩，哈希资源设 `immutable`、入口 `index.html` 设 `no-cache`。
- **必配测试**：① 连库断言扩展自建目录表二级索引齐全且删后自动自愈；② 验证缓存命中零重算且写入新数据推进水位后立即失效；③ 断言全站路由页均为懒加载包装且静态产物与 `index.html` 缓存头及 `gzip` 响应头符合契约。
