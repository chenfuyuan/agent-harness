# 领域探索与宏观架构（Explore & Architect）

带用户看清领域本质、对齐产品形态并锁定难改的系统骨架（`design/SYSTEM.md`），为个性化原型（`bespoke-prototype`）与切片开发提供可靠底座。

## 1. 起步分流（Scale-Adaptive Triage）

动手前先判断复杂度与存量代码环境，**严禁对小需求硬套重流程**：

- **存量代码检测（Brownfield vs Greenfield）**：若仓库内已存在 `src/`、`app/` 等生产代码，必先派只读子代理盘点现有数据正本、公共服务与技术栈约束（先跑 `<Hub-Ref>/bin/ws map <dir>` 提取 AST 符号骨架再按行段精读；若跨多个子系统，按目录拆分为单次 ≤15 个文件的窄边界子代理，防子代理自身触发压缩，只回传结构化结论与 `文件:行号`），确保新设计与既有底座同构。
- **存量平台泛化度核对（防单策略文档误剪通用底座）**：在存量底座上收到用户贴入的**单一方法论/单一策略/单一场景规格书**（哪怕原文档内写有“砍掉/停用其他模块”等激烈措辞）时，提议裁剪存量通用模块前必须作为单向门向用户核实：**这是系统的唯一永久形态，还是通用多策略底座上的 1 号插件/剧本（Playbook #1）？** 严禁未经确认直接把后续扩展要复用的研究、数据或风控底座瘦身删除。
- **三档深度路由**：
  - **L1 明确小工具**：不写调研底稿，当轮对齐边界与不做事项，写 ≤30 行精简 `design/SYSTEM.md`，直接交棒 `bespoke-prototype`。
  - **L2 熟悉领域 / 已有系统新增大模块**：跳过行业科普与算账，聚焦**标杆核心交互拆解 + 边界单向门**，1–2 拍进入原型。
  - **L3 陌生领域新系统（0→1）**：走下面完整的渐进探索。
- **模糊需求与流程自动化前置反向采访（第 0 拍 · 按需触发）**：若用户最初想法仍偏模糊，或在罗列“每天填表/发邮件/点按钮”等既有手工工序，**严禁直接把旧工序翻译成软件**；先扮演资深业务分析师**反向采访 3–5 个关键问题**，剥离出纯粹的**终极业务结果（Outcome）**与 2–3 条 **Anti-Job（系统严禁私自越界的红线，含无人值守无事静默）**，对齐后再展开调研。

## 2. 四源深挖与零凭证探针（防纸上谈兵）

需要外部调研时，优先派子代理执行（当前工具子代理若无外网权限，则由主代理检索并立即落盘 `design/research/<topic>.md` 释放上下文）：

1. **四源交叉查证**：① 官方规则、接口限制与合规红线；② 真实从业者踩坑与耗时卡点；③ 2–3 款代表标杆的**真实屏幕分区、核心控件与状态流转**（为个性化设计储备弹药，不抄公关软文）；④ 单位经济（Unit Economics）与研发/运维成本账。
2. **四级证据打标**：落盘结论必须标注 `[官方文档/实测]`、`[真实界面观察]`、`[从业者复盘]`、`[AI推导-待验]`，严禁把检索摘要包装成确定事实。
3. **隔离只读探针**：遇到公开可测的外部数据源/API 字段疑问，允许在 `/tmp`（或会话 scratch 目录）发起**零密钥、零费用、低频公开只读请求**核实真实返回结构；凡需账号密钥、付费或写操作的验证，一律记入切片单的 `Pre-Build Spike`。
4. **特定领域架构模式卡**：若系统涉及 **AI 输出难人工核查、计算与推理分工、订阅制助手作运行时、多类对象评估标尺、全量 vs 按需数据覆盖、工具系统 vs 单部作品分离**，必读 [domain-patterns.md](./references/domain-patterns.md) 对应条目。

## 3. 三拍渐进节奏（控制单轮认知负荷）

- **第 1 拍（认知与流派对齐，禁写 HTML 原型）**：
  - 用一屏以内篇幅交付：标杆真实长相与流派对比、专家的一天 → 裁出的**“用户的一天”草稿**（标明人做/程序做/AI做/不做，请用户增删）、2–3 条**反目标**（功能全对但算失败的死穴）。
  - 涉及产品流派或主流程走向时，在对话正文附 **10 行级 ASCII 面包板分区草图**辅助判断。
- **第 2 拍（单向门决策 → `SYSTEM.md` v0.1）**：
  - **只为单向门出题**（子系统边界、数据正本归谁、不可逆安全/合规规矩、主工作流形态）：每次聚焦 1–2 个决定，正文讲清业内做法与取舍，推荐置顶，等用户文字确认（用户回复若附带新疑问，先客观评审收敛，不抢跑）。
  - 双向门与底层实现细节（具体阈值、参数、版面比例）直接给合理默认或标“Build 阶段定”。
  - 按 [system-template.md](./references/system-template.md) 写入 `design/SYSTEM.md`（v0.1 候选骨架，控制在 200 行内；单向门推导超 10 条时归档至 `design/decisions.md`）。
- **第 3 拍（交棒原型并回流锁定 v1.0 / 多线总规收口）**：
  - 转入 `bespoke-prototype` 开展视觉比稿与交互原型；原型走查暴露的边界问题回到所属子系统修正，同步锁定 `SYSTEM.md` v1.0，并挑出最薄第一片（每天高频用 + 验证最危险假设）。
  - **多模块存量改造收口顺序（先锁总规 → 子代理隔离探针 → 正交拆线）**：若存量改造横跨多条并行开发线，用户拍板宏观决定后必须在 `Mode: design` 下**先落盘锁定 `design/SYSTEM.md` 与 `design/ROADMAP.md`（写清模块独占写目录与波次边界）**，再派独立子代理执行前置真数据/源码探针（`Wave 0`），严禁在未锁总规前把 >5 个底层源码文件读进主会话。
