# `design/SYSTEM.md` 与 `design/decisions.md` 结构规范

`SYSTEM.md` 面向 AI 与用户跨会话快速把握全局，**只保留现行有效状态，控制在 200 行以内**；被推翻的旧方案交给 git 或 `decisions.md`。

## `design/SYSTEM.md` 模板

```markdown
# <系统名称> — 系统骨架（v0.1 候选 / v1.0 已锁定）

## 1. 定位、日常流与反目标
- **核心目标**：一句话说清解决什么真实问题、给谁用。
- **所属与外部衔接**：独立应用 / 某仓库模块（若维护了 `PORTFOLIO.local.md` 可对照跨仓边界）。
- **用户的一天（主干流）**：
  1. <触发时机与动作>（人 / 程序 / AI）
  2. ...
- **反目标（出现即视为设计失败）**：
  - <例如：日常维护耗时超过手工操作 / 静默产出错误或不可核验的结论>
- **领域硬律与底座前置约束**：<本领域不可违背的因果/合规底线，及若服务潜在多下游业务须提前守住的结构性契约（如时间线因果一致、历史只追加不可篡改、状态幂等对账、权限与审计底线等）>
- **禁越界红线（Anti-Job）**：<系统严禁私自触发的副作用与边界，如严禁未经授权执行外部写操作或外发消息、无人值守无异常时彻底静默禁刷屏>
- **明确不做**：<本系统排除的范围>

## 2. 系统架构与子系统归属
按职责与变化速率清晰切分子系统边界与权威数据正本归属（由具体业务从第一性原理自然推导，不预设固定层数）。

| 子系统 | 职责边界（管什么 / 不管什么） | 权威数据正本（谁唯一写） | 对外交互契约 |
| :--- | :--- | :--- | :--- |
| ... | ... | ... | ... |

## 3. 能力全貌与切片演进
| 能力项 | 所属子系统 | 状态（首片 / 后续 / 不做） | 需求来源（用户确认 / AI建议） |
| :--- | :--- | :--- | :--- |
| ... | ... | ... | ... |

## 4. 关键单向门决定（现行有效）
*(超过 10 条或推导背景较长时，将详细对比移入同目录 `decisions.md`，此处仅留结论指针)*

| 编号 | 决策主题 | 已确认方案 | 核心理由与排除项 |
| :--- | :--- | :--- | :--- |
| D1 | ... | ... | ... |

## 5. 前瞻清单（提前知道，触发再建）
| 架构套路或行业暗坑 | 触发信号（何时才需要动） | 现在做什么（先定规矩 / 留接口 / 只记一笔） |
| :--- | :--- | :--- |
| ... | ... | ... |
```

## `design/decisions.md`（按需创建，平时编码不必全读）

当单向门超过 10 条或某项决策包含复杂算账/合规推演时追加记录：
- `## ADR-00X: <标题>（日期｜状态：生效 / 已被 ADR-00Y 取代）`
- 含：背景约束、备选方案对比、最终裁定、风险与重评触发条件。
