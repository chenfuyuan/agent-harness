# 领域架构模式卡片库（按触发场景读取）

> 提纯自过往跨项目实战经验。仅在当前设计命中对应**触发条件**时采纳，不生搬硬套。

---

## 模式 P1：使用者无法逐条核查 AI 输出时，用系统机制代替人工核查
- **触发条件**：系统引入 AI 做分析、总结、打分或写策略，但用户没时间或专业度逐字核对原文与代码。
- **核心做法**：
  1. **结论结构化降维**：输出一页可行动摘要（粗档位评级 + 核心依据原文锚点 + 证伪条件），不做看似精确却无法验证的百分制黑盒打分。
  2. **程序客观分与 AI 定性分“双轨并列、背离高亮”**：严禁加权合成单分掩盖分歧；显式标出“双好共振 / 客观好但定性有隐患 / 客观差但有催化 / 双差”。
  3. **战绩统计与把握度校准**：记录每次 AI 判断并在事后对照真实结果统计命中率；注意剥离模型知识截止日前的**参数型前视偏差**，重叠观察窗口去重计数。
  4. **防未来/风控检查固化在引擎层**：不允许做成可被 AI 或用户随手关掉的配置开关；界面同屏展示“AI 这次查了哪些源、受什么只读限制”。

## 模式 P2：能算的交给程序，花钱的 AI 推理必须留下可复用资产
- **触发条件**：系统同时包含数据处理、指标计算与大模型调用。
- **核心做法**：
  1. **AI 用途准入三问**：为什么非 AI 不可？引用的数字从哪个确定性程序接口来？用哪档模型？未列入清单的一律写确定性代码。
  2. **成果资产化**：高成本推理按固定结构落盘归档，后续同类任务先读存量档案只跑增量；事件破坏前提或超过半衰期才重审，不盲目定时全量重跑。

## 模式 P3：用订阅制 AI 助手承担“人在场”重度推理（双池算力路由）
- **触发条件**：个人自用系统希望复用已付费的 Claude Code / Codex / AGY 订阅降低 API 账单。
- **核心做法**：
  1. **按人在不在场分流**：人在场的研究、问答、写策略草稿走本地订阅助手；无人值守夜间批处理走 API（优先月度赠金池 + 硬预算护栏）。
  2. **只交草稿、决定权留系统**：外部助手在隔离目录通过只读查询命令与收件箱文件包交互，只能提交“待确认草稿”，严禁暴露直接改库或下单接口。
  3. **单工具阶段文件契约 + 干净子代理盲审**：长链路分析在单工具内以文件契约串联（保缓存）；需反方挑刺时剥离推理过程，拉起零上下文干净子代理盲审。

## 模式 P4：多类异质对象筛选与评估，按“对象类型 × 使用周期”双维拼装标尺
- **触发条件**：系统需对大量性质迥异的标的（如不同属性股票、选品、选题）做筛选或打分。
- **核心做法**：拒绝一套万能公式通吃，也拒绝建几十套孤立模板。拆为 **对象类型**（决定看哪些核心指标与一票否决红线，系统自动初判+允许人工改判）× **使用阶段/周期**（决定容忍度与退出条件），两维正交组合出评估标尺。

## 模式 P5：数据的采集覆盖范围必须配得上消费它的范围
- **触发条件**：系统包含横向筛选、全市场排名、知识图谱路径检索或历史回测。
- **核心做法**：沿数据流核对“怎么取（全量常备 vs 按需点查）”与“怎么用（单点问答 vs 全局比较/回测）”。**凡用于全局比较、筛选或回测的字段，底层必须是按类别全量采集且补齐带公开时间戳（PIT）的历史数据**；按需抓取的数据只准用于单对象点查，严禁混入回测造成幸存者/关注度偏差。显式区分“值为无”与“数据缺失”。

## 模式 P6：分离“造工具的系统设计”与“单部作品的内容设计”
- **触发条件**：涉及游戏、AI 小说、AI 漫剧、短视频等内容生产方向。
- **核心做法**：本工作流用于设计**生产流水线、编辑器框架与埋点约定**；单款游戏的关卡数值、单部小说的剧情人设属于“作品设计”，必须放在作品自己的目录里靠可玩/可读版本快速试错迭代，不走系统架构规格流程。
