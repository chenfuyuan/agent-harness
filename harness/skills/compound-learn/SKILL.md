# 三级经验进化飞轮（Compounding Learning & Graduation）

单纯往一份长文档里无限追加“注意事项”，最终只会变成**没人翻的死文档坟场**或**撑爆上下文稀释注意力的噪音**。本技能通过**按需唤醒 + 事不过二强制毕业 + 硬容量淘汰**机制，把实战踩坑转化为零膨胀的永久免疫力。

## 1. 四个自动触发时机

出现以下任一情况时，在任务收尾前主动执行沉淀评估（草拟 **3–5 行**精炼提案请用户点头确认，不长篇大论）：

1. **真故障闭环**：刚走完 `systematic-debugging` 修掉一个线上或测试未覆盖的真实缺陷；
2. **对抗审查拦截**：`adversarial-review` 揪出了主对话遗漏的 `Blocker` 级漏洞；
3. **用户纠偏唤醒**：用户在对话中指出了 AI 方案的思维盲区、浅补丁惯性或领域边界误判；
4. **容量水位预警**：运行 `<Hub-Ref>/bin/ws learn status` 发现某模块 `AGENTS.md` 或母仓 `playbooks/` 接近硬上限。

## 2. 双归属分流与「硬规则优先」毕业铁律

每条新经验必须先按**归属作用域（本业务仓 vs 母仓 `agent-harness`）**分流，再按**形态（硬防线优先于文字备忘）**落入唯一位置，严禁业务特例外溢母仓或多处重复抄写：

### A. 本业务仓沉淀（默认随当前开发线闭环，留在自己库内）
- **首选 · 代码与规则硬防线（Tier 3 项目规则）**：凡纠错后追问“下次 AI 再犯谁先拦住”，答案若是人，立刻将分层禁令、公开入口或高危 API 写入项目根 **`.harness-rules.json`**（30 秒零摩擦毕业，由 `ws check` 自动拦截），或沉淀为自动化回归/属性测试与脱敏 `tests/fixtures/` 黄金样本（**仅拦结构/语义硬错，绝不对业务代码设硬行数/字数红灯**）。
- **次选 · 模块极薄备忘（Tier 1 模块契约）**：仅复杂核心模块按需建 `src/<mod>/AGENTS.md`（建议 ≤20 行，硬上限 **25 非空行**），只写机器静态规则拦不住的纯业务不变量与单测命令；公开入口与机械禁区一律移入 `.harness-rules.json`。
- **切片复盘**：本片业务特有边界与上线观察回填至 `design/slices/NN.md#4 真用复盘`。

### B. 母仓 `agent-harness` 通用沉淀（默认写「无」，必须单独确认后独立沉淀）
- **准入双门槛（缺一不可，严禁凑数）**：① 跨项目通用、在其他仓库大概率复现的工程反模式或工作流卡点；② **零私有业务信息**（严禁混入业务表名、领域私有名词、本机路径或密钥）。不满足即留在业务仓。
- **首选 · 母仓代码硬防线（Tier 3 母仓代码）**：优先改进 `bin/ws`、`harness/guards/`（如 `harness_guard.py` / `mode_guard.py`）并配 `tests/test_harness.py` 回归测试。
- **次选 · 跨项目错法卡与技能精修（Tier 2）**：`<Hub-Ref>/harness/playbooks/Fxx-<slug>.md`（`INDEX.md` ≤ **35 非空行**，总卡 ≤ **10 张**，单卡 ≤ **45 非空行**；开发与排障按触发场景点读）或精简修订 `harness/skills/`、`harness/rules/`。

> **毕业即删字 + 严禁刷指标**：硬防线生效后立刻删掉旧口头叮嘱；文档容量满额须走「毕业进代码」或请人裁决，**严禁把多条压成超长单行或私自删老规则凑数**；`ws learn check` 同时硬拦过期 `stub-ok`。

## 3. 两段解耦的标准沉淀动作流（不阻塞业务收尾）

1. **验收时拆两栏呈报（严禁提前合流或跨仓偷改）**：运行 `<Hub-Ref>/bin/ws learn status [project_dir]` 一屏查看模块契约、`.harness-rules.json` 与全仓豁免债（`stub-ok`/`ignore-ok`/`boundary-ok`/`rule-ok`）；在交付验收（`full` 图文报告或 `fast` 一屏摘要）中**强制拆成两栏**请用户确认：
   - **本业务仓拟沉淀**（3–5 行，优先提议 `.harness-rules.json` 规则与回归测试）；
   - **母仓 `agent-harness` 通用候选**（默认写 `无`，仅确属跨项目通用且零业务词时列 ≤3 行）。
2. **用户确认后先完成本业务仓闭环**：在当前开发线写入经确认的**本业务仓**沉淀、清理过期 `stub-ok` 占位并提交，运行 `<Hub-Ref>/bin/ws line distill`（仅核验当前业务仓水位、护栏合法性与过期占位并锁定 `distilled_head`）→ `ws line sync` → `ws line rm <slug>`。**严禁在业务工作树会话里顺手跨仓改 `agent-harness`**。
3. **母仓候选确认后的轻交接（独立沉淀）**：若用户同时确认了**母仓 `agent-harness` 通用候选**，在业务线收尾回复末尾直接输出一段 **≤8 行、已脱敏的可直接粘贴提案块**（写明：通用痛点/根因、建议改动位置、回归验证项）；随后在独立 `agent-harness` 会话确认落盘、跑绿 `python3 tests/test_harness.py`、提交推送并按需运行 `bin/ws sync`。
