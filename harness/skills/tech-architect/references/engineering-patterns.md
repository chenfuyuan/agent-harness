# 跨领域核心代码与数据工程模式卡（Engineering Patterns）

> 提炼自工业界成熟开源项目与高可靠系统工程实践。命中触发条件时采纳其**分层与状态机内核**，存储与运行载体按项目实际规模轻量化落地。

---

## 模式 E1：铜·银·金奖章数据管道（Medallion）与 PIT 时点锁
- **触发条件**：系统需接入会过期销毁或口径多变的外部数据源、处理非结构化抽取，或支撑历史回测与事后归因复盘。
- **核心做法**：拒绝单表原地 `UPSERT` 覆盖毁灭原始现场，在单机（如 `Parquet/DuckDB + SQLite/PG`）即可实现三层隔离：
  1. **铜层（Bronze · 原始封存）**：0 加工、只追加（Append-only）落盘原始报文或原文，记录真实采集时间 `ingested_at` 与披露/完结时间 `available_at`。上游接口过期或下游算法重构时可随时 100% 重放。
  2. **银层（Silver · 对齐与防未来）**：清洗去重、统一主键与时间粒度；**显式区分“断流/未披露（缺数 Gap/NULL）”与“真实零值（0）”**；所有供回测或历史还原的查询硬锁 `available_at <= as_of`（K线/周期数据硬锁已完结 `closed_at <= as_of`），在引擎层根除前视偏差。
  3. **金层（Gold · 场景读视图与客观判卷）**：按前端座舱、筛选榜单或知行纪律评估预聚合，保证展示层零复杂业务算式、毫秒级直读。

## 模式 E2：统一时钟与事件驱动同构内核（Unified Clock & Event Core）
- **触发条件**：系统同时包含“历史回测/仿真回放”与“实时生产监控/自动执行”（如量化交易、规则风控、仿真调度）。
- **核心做法**：严禁“回测写一套向量化脚本、实盘另写一套 `while` 循环”。提炼统一的策略/规则上下文接口（如 `on_bar(ctx)` / `on_event(ctx)`），内部只读注入的抽象时钟 `ctx.clock.now()` 与银层 PIT 数据；回测运行器（喂历史事件流 + 强制扣减真实手续费/滑点/费率摩擦）与实盘运行器（喂实时网关流）复用同一份策略代码。

## 模式 E3：快照 + 增量序号对齐自愈状态机（Snapshot + Delta FSM）
- **触发条件**：通过 WebSocket 或流式协议在本地维护实时深度盘口（OrderBook）、协同画布状态或增量缓存。
- **核心做法**：严禁盲目直接应用增量包导致断线后产生“幽灵脏状态”。标准状态机：`CONNECTING`（先缓存增量流）→ `SNAPSHOT_SYNC`（拉取全量快照并丢弃 `seq <= snapshot_seq` 的旧包）→ `LIVE`（逐包核对连续序号或 `CRC32 checksum`）→ 一旦检测到断序或校验失败立即切回 `RESYNC` 清空脏状态重拉快照。

## 模式 E4：本地意图先行 + 幂等键与双路对账（Idempotent Outbox & Reconcile）
- **触发条件**：调用外部交易下单、撤改单、支付扣款等不可逆副作用接口。
- **核心做法**：
  1. **先落账后发网**：发外部请求前先在本地事务库写入 `PENDING_SUBMIT` 意图并生成确定性客户端幂等单号（如 `clOrdId`）；
  2. **超时先查单禁盲重发**：遇到网络超时或进程重启，恢复循环必先凭幂等单号调远端查询接口对账状态，严禁无脑重发造成双倍开仓/扣款；
  3. **在途并发节流**：对改单/撤单维护 `in-flight ack` 锁（上一笔请求未收到交易所确认前合并或排队后续改价，防触发并发改单上限报错）。

## 模式 E5：纯函数领域核 + 薄命令外壳（Functional Core, Imperative Shell）
- **触发条件**：系统包含仓位算账、风控熔断、几何画线、排班计费等高密度确定性逻辑。
- **核心做法**：将所有算式、状态转移判定与阈值校验剥离为 **100% 无外部 I/O（不碰数据库、网络、系统时间）的 `domain/` 纯函数模块**，确保全套边界单测无需起容器在数秒内跑完；数据库读写与第三方 API 适配器统一收口在 `infra/`，由薄应用服务编排。

## 模式 E6：单一真源强类型跨端生成（Schema-First Codegen）
- **触发条件**：前后端分离或跨语言服务高频协作。
- **核心做法**：以后端路由与数据模型（如 FastAPI Pydantic → OpenAPI JSON，或 Protobuf）作为唯一契约真源，通过脚本（如 `openapi-ts`）自动生成前端 TS 类型与请求客户端并纳入 `scripts/check` 校验，杜绝双端手抄字段名导致的静默拼写 Bug。
