# `design/TECH.md` 工程架构底座规范

`TECH.md` 是连接 `SYSTEM.md`（业务做什么）与 `src/`（代码怎么写）的唯一工程架构蓝图，**控制在 100 行以内**，聚焦不可随意打破的底层边界、数据与状态契约。具体架构范式与存储形态完全由当前项目的实际需求与第一性推导决定，**严禁预设固定分层或套用无关领域模板**。

```markdown

- **语言 / 框架 / 存储介质**：<贴合当前真实规模的技术选型、包管理器与进程/部署拓扑>
- **标准命令**：开发 `scripts/dev` ｜ 全量门禁 `scripts/check`（及跨端契约命令，若有）

## 2. 数据架构与持久化边界
- **权威正本与读写形态**：<结合当前项目实际读写特征、一致性与演进要求独立推导：存储结构、唯一写者、迁移与数据治理纪律>

## 3. 核心抽象、流转与容错边界
- **核心引擎与状态流转**：<当前项目最关键的模块抽象、生命周期或并发协作机制>
- **容错、幂等与恢复策略**：<失败隔离、不可逆外部写操作幂等对账与异常重启恢复方式>

## 4. 代码目录地图、声明式护栏与验证策略（唯一事实源：`.harness-rules.json`）
- **目录与单向依赖**：<按项目实际复杂度划分模块边界，不强行过度分层>
- **机械边界代码化**：模块公开入口（`public_entries`）、单向分层禁令（`layer_bans`）与高危 API 封禁（`pattern_bans`）一律写入项目根 `.harness-rules.json`，由 `ws check` 硬守卫，不靠口头约定。
- **验证策略**：<核心逻辑的单测 / 属性测试 / 集成验证方式>
```
