# `design/TECH.md` 工程架构底座规范

`TECH.md` 是连接 `SYSTEM.md`（业务做什么）与 `src/`（代码怎么写）的唯一工程架构蓝图，**控制在 100 行以内**，聚焦不可随意打破的分层铁律、数据管道与核心状态机契约。

```markdown
# <项目名称> — 技术与代码架构底座（TECH）

## 1. 技术栈与运行拓扑
- **后端 / 前端 / 存储介质**：<明确具体版本、包管理器与进程编排方式，贴合实际规模>
- **跨端契约与标准命令**：开发 `scripts/dev` ｜ 全量门禁 `scripts/check` ｜ 契约生成 `<命令>`

## 2. 数据管道与存储分层（如铜·银·金奖章流或事务正本）
- **铜层 / 原始事件封存**：<哪些外部报文或流水只追加原样落盘、保可重放>
- **银层 / 清洗对齐与时点安全**：<时间粒度对齐、缺数 vs 零值标记、`as_of` 防未来约束>
- **金层 / 聚合读视图与事务库**：<座舱直读模型、本地事务状态表归属>

## 3. 核心引擎抽象与状态机契约
- **关键状态机 / 同构接口**：<如：订单生命周期 FSM、回测与实盘共享的 Clock/Strategy 接口、盘口重同步状态机>
- **并发、幂等与容错护栏**：<如：`clOrdId` 幂等对账、改单 in-flight 节流、断线自愈策略>

## 4. 代码目录地图与单向依赖铁律（由 `scripts/check` 硬守卫）
- `src/domain/`：纯计算与状态转移规则（零数据库/网络 I/O 依赖，纯内存单测全覆盖）
- `src/infra/`：外部网关适配器与存储实现
- `src/app/`（及 `frontend/`）：用例编排、API 暴露与直接导入 `tokens.css` 的界面组件
- **跨模块红线**：外部仅准经模块唯一公开入口调用，严禁跨层深层导入或展示层内嵌业务算式。
```
