# 代码与数据工程架构探索（Technical & Code Architecture）

产品设计解决“解决什么、怎么交互”，代码架构决定“系统稳不稳、数据脏不脏、能不能演进”。本技能在业务设计与编码实现之间建立专门的**工程架构探索关卡**——**从本项目真实体量与领域硬律出发原生推导结构，再拿业内成熟开源工程做压力测试与局部采珠**，并将结论编译为可执行的代码契约。

## 1. 规模自适应分流（防过度设计）

动手前先锚定项目的真实运行规模（如个人单机自托管 vs 多人协作 SaaS）与 `design/SYSTEM.md` 中锁定的领域硬律，**严禁把简单工具吹成分布式微服务怪兽**：

- **L1 轻量单功能工具（低状态/无复杂并发与回溯）**：跳过外部源码深挖，当轮明确薄目录分层与存储格式，写 ≤40 行精简 `design/TECH.md`，直接交棒 `slice-build`。
- **L2 / L3 核心业务系统（含实时流状态、多源数据管道、离线重放与仿真、复杂事务或高可靠网关）**：走下面完整的三步工程架构探索。
- **存量仓库扩展**：必先跑 `<Hub-Ref>/bin/ws map <dir>` 与精读既有 `design/TECH.md`，新模块架构须融入现有分层守卫，不造割裂的“国中之国”。

## 2. 第一性原理推导 + 业内开源架构照妖镜（只作参考、禁整套搬运）

需要外部调研时，检索同技术子域的成熟工程方案并立即落盘 `design/research/tech-<topic>.md` 释放主会话上下文：

1. **先基于本项目实际约束与领域硬律原生推导**：结合 `design/SYSTEM.md` 的核心数据流、并发特征与底座前置约束（如时序不可篡改、幂等对账、可回放重算等），从第一性原理先推导出贴合当下体量的最简进程内分层与存储边界，**不先入为主套用重型框架或大厂目录模板**。**防腐层中立命名铁律**：核心领域模型与标准持久化字段严禁泄漏外部第三方供应商的私有命名或混合单位，外部协议差异一律收敛在 `adapters/` 边界内。
2. **再用开源标杆做“压力测试 & 局部采珠”（严禁整套搬运！）**：针对核心技术难点（如实时流同步、历史重放、多源清洗、崩溃恢复、插件隔离），挑选 2–3 个业内公认标杆开源项目拆解其代码骨架（数据存储边界、核心状态机、并发/异步边界、容错与对账机制），标注 `[官方文档/源码]`、`[工程实践复盘]`、`[AI推导-待验]`，只做三件事：
   - **查漏**：核对我们的原生构想是否漏掉了标杆用血泪换来的边界容错或数据一致性坑；
   - **破惯**：强制剥离脱离当前规模的分布式重基建（如单机日均百万行以内严禁盲目引入 Kafka / Flink / K8s 多服务编排）；
   - **采珠**：仅将已被验证的局部内功机制提纯吸收进本项目的简洁架构，**严禁把无关领域的历史套路或标杆整套架构生搬硬套进来**。

## 3. 技术单向门拍板与三层契约固化（防八股文腐烂）

1. **只为技术单向门出题**：默认每次只聚焦 **1 个**最关键的难返工底层决定（如：核心架构范式与数据存储形态、同步 vs 异步处理边界、进程拓扑与外部依赖边界；仅当两项强耦合不可拆时最多合并 2 个），在正文讲清贴合当前规模与需求实际的真实取舍，**默认亮明推荐方案、推荐原因，并必须同时写明“什么前提下不该选它”**，等用户确认。框架小版本、内部工具库等双向门直接给经过验证的合理默认。
2. **拒绝长篇观赏文档，结论直接编译进三处硬约束**：
   - **`design/TECH.md`（及 L3 跨切片详设位）**：按 [tech-template.md](./references/tech-template.md) 固化一页硬核架构底座（控制在 100 行内：技术栈、数据分层流向、核心状态机与不变量、验证策略、标准门禁命令）；若 L3 复杂系统存在**跨多个切片共享的核心接口协议、插件抽象或标准数据模型**，允许在 `design/architecture/<topic>.md`（顶部必带 ≤30 行 `TL;DR` 速查，由 `TECH.md` 指针引用）沉淀跨切片详细契约，既不撑破 `TECH.md` 100 行上限，又防各切片各自为政（单个外部接口的具体字段怪癖仍留给对应切片的 `Pre-Build Spike` 实测）；
   - **声明式硬护栏（`.harness-rules.json`）**：在 `Slice 00` 直接落盘项目根 `.harness-rules.json`（`public_entries` 模块唯一入口、`layer_bans` 单向分层与 I/O 禁令、`pattern_bans` 高危原生 API 封禁与白名单封装目录），交由 `ws check` 原生强执，免重复手写样板脚本；
   - **验证策略与交棒 `slice-build`**：明确 `domain/` 纯计算核与状态机采用“手算 TDD + 随机序列属性测试（Hypothesis / fast-check 或纯标准库随机种子循环）”，并将复杂算法下放至各垂直切片落地。
